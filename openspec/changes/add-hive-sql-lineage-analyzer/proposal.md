# Change: Add Hive SQL Lineage Analyzer

## Why

工作流提交运行时，系统会批量获取工作流中的多个 Hive 任务脚本并解析血缘。每个任务脚本可能包含多条 Hive SQL 语句，并且这些语句在同一个 Hive Session 内执行，因此解析工具需要支持：

- 任务版本维度，例如 `V1`、`V2`、`V3`。
- 脚本级解析，而不是只解析单句 SQL。
- 按需解析表血缘、字段血缘，或同时解析两者。
- 按需解析显式 `JOIN ... ON ...` 条件，以及逗号连接中写在同一查询块 `WHERE` 后的跨来源关联条件；该能力不属于正式血缘。
- 当调用方开启视图展开时，读取 Hive 视图定义并追溯到真实上游表；字段级视图展开作为后续增强。
- 对视图对象类型和缺失元数据做缓存，避免一段脚本或一个工作流内重复查询同一对象。
- `set` 语句设置的 Session 变量在后续语句中生效。
- 运行时变量残留时的兜底替换。
- 临时表血缘在当前 Session 内串联。
- Hive 元数据缓存，避免批量解析时频繁访问 Hive Metastore。

## What Changes

新增一个 Hive SQL 血缘解析能力，提供脚本级入口，但输出和持久化粒度按需要记录的单条 SQL 语句组织：

```java
LineageAnalyzeResult analyzeScript(LineageAnalyzeRequest request);
```

该能力输出：

- 语句级解析结果，一条需要记录的 SQL 对应一条 `StatementLineageResult`。
- 产生血缘或解析失败的语句保留原始 SQL 和变量替换后的 SQL。
- 产生血缘的语句包含自身产生的表级血缘和字段级血缘。
- 解析失败的语句记录解析状态、失败编码和失败原因，便于后续从 TDSQL 捞取分析。
- 调用方可通过解析模式选择只解析表血缘、只解析字段血缘，或同时解析。
- 调用方可通过独立功能开关选择是否解析 Join 条件；Join 条件解析结果不计入表血缘或字段血缘。
- 字段血缘结果必须体现源字段集合和加工类型，并且必须尽量提取表达式、函数名和复杂表达式标记；表达式无法稳定提取时不阻断字段血缘，但需要通过结果字段标记。
- 变量替换、元数据缺失、解析降级等 warning。

血缘产生口径调整为：**只有同时存在明确输入数据对象和明确输出数据对象时，才产生正式血缘。** 单独 `select ... from source` 只有输入没有输出，完全忽略，不产生正式血缘、不产生查询依赖信息、不写图数据库边。`insert ... values (...)` 完全忽略，不产生正式血缘、不产生写入事件、不写图数据库边。

## Impact

- 调用方需要传入一段 Hive SQL 脚本，以便解析器维护 Session 级变量和临时表上下文。
- 调用方持久化时建议按 `StatementLineageResult` 单条语句结果落库，默认只落产生血缘或解析失败的语句，避免单行字段过大和无效记录过多。
- Join 条件解析结果建议单独落库，并通过 `statementId` 关联语句主记录；纯查询语句不产生正式血缘，但开启 Join 条件解析时仍可返回语句级结果。
- 脚本级返回对象仅作为内存中的批量包装，不建议作为 TDSQL 的一行记录持久化。
- 调用方需要传入 `workflowId`、`taskId`、`taskVersion`，用于区分不同任务版本的解析结果。
- 只解析表血缘时，解析器默认不查询 Hive 表字段元数据；只有字段血缘或显式开启视图展开时才按需加载元数据。
- 元数据查询通过 `MetadataProvider` 抽象，解析器内部叠加工作流级缓存和进程级 TTL 缓存。
- 注释移除与 SQL 分割先保留扩展点，后续接入已有逻辑。

## Out Of Scope

- 不实现 Hive SQL 注释移除和语句分割的完整逻辑，只定义接口占位。
- 不直接实现 Hive Metastore 客户端，只定义 `MetadataProvider`。
- 不保证解析所有 Hive 方言边界语法，无法解析的语句以 warning 形式返回。
- 不处理纯查询语句和 `insert ... values (...)` 语句的依赖、事件或图边。
