# Hive Lineage V2 Engine

## ADDED Requirements

### Requirement: 词法语法绑定与血缘阶段解耦

系统 SHALL 分开定义 Lexer、Parser、SyntaxNormalizer、SemanticBinder、IR Verifier 和血缘分析的输入输出及诊断。血缘阶段 SHALL 只消费已验证 Bound IR，禁止读取 SQL、Token、AST、Provider 或重做名称解析。V1 字符串、别名 Map 和来源抽取模型 SHALL 不成为新 IR 的基类或核心输入。

#### Scenario: 前端独立于元数据

- **假设** 不提供 Provider 或 Session 目录
- **当** 对已展开 SQL 分词、语法解析和归一化
- **那么** 可以得到词法/语法产物及对应诊断
- **并且** 前端不推导物理字段来源或因元数据缺失失败

#### Scenario: 绑定与血缘职责隔离

- **假设** Binder 接收 Syntax IR、显式上下文和需求
- **当** 生成绑定结果并由血缘分析消费
- **那么** Binder 不生成血缘结果集合，血缘不访问 Scope 名称索引或 Provider
- **并且** Session 提交和旧格式输出由编排/适配层负责

### Requirement: 独立词法产物与语法输入

系统 SHALL 使词法输出成为语法解析的显式输入，并保留 Token、Trivia 和位置。Hive/ANTLR 类型 SHALL 留在方言 adapter；允许内部共用 Token buffer，但不能以重复字符串解析或隐式全局状态冒充分层。

#### Scenario: Parser 消费已有词法产物

- **假设** 已取得 LexedUnit
- **当** 调用 Parser
- **那么** 使用该产物解析，不重新对原字符串分词
- **并且** 可单独测试 Lexer 输出和 Parser 输入，两者不包含业务血缘规则

#### Scenario: 更换前端不改变分析契约

- **假设** 不同词法/语法实现生成同等结构的 Syntax IR
- **当** 使用同一 Binder 和血缘规则
- **那么** 不修改血缘主流程，结果仅受明确的方言语义和输入事实影响
- **并且** Hive TOK/AST 不进入核心模型

### Requirement: Syntax IR 与 Bound IR 独立强类型模型

系统 SHALL 分开定义结构化 Syntax IR 与不可变 Bound IR。Syntax IR 保留查询结构而不含来源集合，Bound IR SHALL 表达身份、关系、表达式、有序输出及已绑定写入，不依赖表达式字符串决定语义。

#### Scenario: 查询结构与求值语义分开

- **假设** 查询包含 GROUP、HAVING、窗口、排序、截取和子查询
- **当** 归一化和绑定
- **那么** Syntax IR 保存对应结构，Binder 按方言生成语义关系
- **并且** 不把文本排列顺序当作求值顺序，不丢弃行集影响结构

#### Scenario: 写入先绑定再推导

- **假设** 有目标列及分区的写入
- **当** 调用血缘分析
- **那么** SinkPlanner 已形成目标字段身份与赋值表达式或明确 UnknownMapping
- **并且** 血缘不查询目标元数据或猜测目标列

### Requirement: 显式引用状态与绑定覆盖

系统 SHALL 区分 SlotRef、QualifiedFieldHandle、UnknownReference、UnknownOutputSegment 和 NotRequestedRegion，输出 BindingCoverage。Bound IR SHALL 不包含延迟 Parser/Binder/Provider 回调。

#### Scenario: owner 已知而存在性未验证

- **假设** Join-only 引用物理 a.id 且未请求 schema
- **当** 绑定该引用
- **那么** 形成 owner 已确定、existence=UNVERIFIED 的 QualifiedFieldHandle
- **并且** 不声称字段存在性已验证，不从派生表名拼接物理来源

#### Scenario: 需要更多绑定信息

- **假设** 某区域未请求或输出宽度未知
- **当** 后续扩展分析需求
- **那么** 编排层重新请求 Binder 并验证新分析单元
- **并且** 血缘引擎不从 IR 回调读取 SQL/schema，不造星号 Slot 或精确错位映射

### Requirement: Bound IR 独立校验与稳定身份

系统 SHALL 在推导前校验结构和所请求绑定范围，包括节点唯一、Slot 可达、作用域、关联引用、输出映射和未知宽度。身份 SHALL 不随请求能力或求值顺序改变。

#### Scenario: IR 不变量不成立

- **假设** 手工 IR 含非法 Slot、关联范围或集合映射
- **当** Verifier 检查
- **那么** 返回独立 Verification 诊断，不让无效范围产生确定血缘
- **并且** 不尝试扫描源码修复模型

#### Scenario: 同输入多能力结果对齐

- **假设** 同一语句分别请求表、字段、Join 能力
- **当** 按需绑定
- **那么** 对应 NodeId、QueryBlockId 和已声明 SlotId 可稳定对齐
- **并且** 未请求区域不被当作绑定失败

### Requirement: 源码附件不决定依赖

系统 SHALL 将 SourceRef、原表达式文本和词法显示信息作为定位/渲染附件。IR 推导 SHALL 不依赖这些附件取得业务来源。

#### Scenario: 无 SQL 的 IR 血缘分析

- **假设** 使用构造器生成有效关系、表达式和写入 IR，未提供 SQL、Parser 或 Provider
- **当** 推导血缘
- **那么** 可以得到值、条件和行集事实
- **并且** 没有表达式文本仅影响显示提取质量

#### Scenario: 相同 IR 更换原文附件

- **假设** 两个已绑定模型语义相同而原文或显示别名不同
- **当** 推导来源
- **那么** 来源结论相同，源码和渲染差异单独呈现
- **并且** 不重新扫描附件推导字段

### Requirement: 外部定义统一前端准备

系统 SHALL 由编排层通过相同词法/语法前端准备视图和外部脚本定义为 SyntaxTemplate，Binder SHALL 只递归绑定结构化定义。缺失模板时返回定义需求，禁止 Binder/血缘直接解析定义 SQL。

#### Scenario: 首次读取视图定义

- **假设** Provider 提供视图定义且尚无语法模板
- **当** Binder 需要展开该定义
- **那么** 返回 NEEDS_DEFINITION，由 DefinitionCoordinator 获取文本并准备模板后重新绑定
- **并且** Parser 不被 Binder 或血缘调用，定义上下文和缓存实例隔离

#### Scenario: 定义循环或解析失败

- **假设** 视图循环、定义文本语法错误或包含来源不可取得
- **当** 准备和绑定模板
- **那么** 在相应阶段返回诊断与可保留边界
- **并且** 血缘不通过再次解析文本尝试猜测来源

### Requirement: 独立 V2 内核与 V1 并行保留

系统 SHALL 新增独立 V2 实现，保留 V1 生产实现、默认入口、既有 DTO 和测试素材。新增代码 SHALL 兼容 Java 8、Maven 和当前 Hive Parser 4.0.1 基线。

#### Scenario: 显式选择 V2 实现

- **假设** 调用方继续使用现有请求和分析接口
- **当** 调用方显式构造 V2 实现
- **那么** 请求通过新增适配器进入 V2 内核并返回现有结果类型
- **并且** V1 实现仍能独立运行，默认入口不变
- **并且** V2 不调用 V1 投影、血缘生成和展开逻辑

#### Scenario: 文档确认前不开始实现

- **假设** 本变更尚未得到用户确认
- **当** 创建或审查本需求
- **那么** 只新增和验证本变更文档
- **并且** 不修改生产代码、V1 测试、测试 SQL 或构建行为

### Requirement: 统一语法模型与方言隔离

系统 SHALL 通过 Hive adapter 转换 AST 为统一未绑定模型，语义和血缘模块 SHALL 不依赖 Hive AST 类型。方言、Parser 和规则版本 SHALL 作为显式分析依据。

#### Scenario: Parser 适配输出稳定模型

- **假设** SQL 已通过脚本前端形成当前语句
- **当** Hive adapter 解析成功
- **那么** 下游通过表达式、关系、语句及源码位置模型工作
- **并且** 不在业务规则中直接遍历 TOK 节点

#### Scenario: 主解析器失败后可诊断降级

- **假设** 主 Parser 无法识别已有回归中的语法
- **当** 配置允许降级前端
- **那么** 降级产物仍使用统一模型，记录主失败和降级依据
- **并且** 不通过调用 V1 结果生成器伪装为独立 V2 成功
- **并且** 没有可靠产物时明确报告未支持或失败

### Requirement: 能力规划与渐进绑定

系统 SHALL 在分析前规划所需事实，支持对象、条件字段、输出结构分层绑定。SchemaState SHALL 区分未请求、已知和未知。

#### Scenario: 表级分析不要求完整字段绑定

- **假设** 只请求表血缘且未开启视图展开
- **当** 语句包含星号、函数或不可确定的字段结构
- **那么** 可识别的输入输出对象仍能生成表依赖
- **并且** 不为了字段分析加载元数据或返回字段缺失 warning

#### Scenario: Join-only 不绑定无关投影

- **假设** 只请求 Join 条件且 ON 为限定物理字段
- **当** SELECT 投影含星号
- **那么** 条件对象和字段可独立分析，无需展开整个投影
- **并且** 未请求的 schema 不导致失败

### Requirement: 字段身份与作用域

系统 SHALL 使用对象身份、关系实例身份、有序 Slot 和嵌套路径表达字段，作用域 SHALL 明确控制 CTE、别名、派生表和关联引用的可见性。

#### Scenario: 自连接和重复输出名称

- **假设** 同一物理表被扫描两次或投影有重复字段名
- **当** 完成所需字段绑定
- **那么** 两次扫描和各输出 Slot 保持不同身份
- **并且** 不按显示名称覆盖输出或任意猜测歧义

#### Scenario: 嵌套与集合分支作用域隔离

- **假设** CTE、子查询或集合分支重复使用别名
- **当** 递归分析字段引用
- **那么** 名称仅在对应可见范围中解析
- **并且** 关联引用显式指向外层关系，不泄漏兄弟分支名称

### Requirement: 原子关系表达式组合

系统 SHALL 基于表达式、关系和语句效果规则组合分析，表达式与关系 SHALL 能相互嵌套。规则模型 SHALL 承接已有聚合、窗口、集合、EXPLODE 和子查询功能。

#### Scenario: 子查询表达式与聚合组合

- **假设** 投影含标量子查询或 COUNT(*)
- **当** 计算依赖
- **那么** 内层关系依赖和输出字段分别追溯
- **并且** COUNT(*) 不伪造成全部输入字段值来源

#### Scenario: 窗口与多输出生成关系

- **假设** 查询包含窗口函数或 LATERAL VIEW EXPLODE
- **当** 形成关系输出
- **那么** 参数、窗口分区、排序和生成字段有明确规则及输出 Slot
- **并且** 不依赖完整 SQL 模板匹配

### Requirement: 依赖角色与未知质量

系统 SHALL 分开保存值、条件、行集、结构、定义和存储依赖，空依赖 SHALL 与未知来源区分。分析 SHALL 分别记录合法性、覆盖、精度及效果确定性。

#### Scenario: 过滤字段不成为投影值来源

- **假设** 上游表达式只用于过滤最终 id 输出
- **当** 递归传播依赖
- **那么** 表达式来源通过条件或行集角色传播
- **并且** 不直接作为 id 的值来源输出

#### Scenario: 已知来源与未知函数行为并存

- **假设** 未知 UDF 参数中有可识别字段
- **当** 推导函数依赖
- **那么** 保存这些参数来源，同时保留函数行为未知
- **并且** 不把未知行为转换为已确定空来源或整条失败

### Requirement: 写入映射与待提交效果

系统 SHALL 由独立 SinkPlanner 校验输出顺序、目标字段和分区，语句效果 SHALL 支持多个结果及目标，并在校验后才提交。

#### Scenario: 静态与动态分区映射

- **假设** 目标同时包含静态和动态分区
- **当** 规划写入
- **那么** 静态分区按常量单独记录，动态分区参与位置映射
- **并且** 无来源表达式不产生虚构字段边

#### Scenario: 输出数量未知与已知不匹配

- **假设** 源 schema 缺失或已知输出宽度与目标不同
- **当** 校验目标映射
- **那么** 未知宽度报告无法确定，不伪装为数量不匹配
- **并且** 已知不匹配按明确映射契约报告，不生成错位字段

### Requirement: 脚本 Session 与工作流生命周期

系统 SHALL 每脚本顺序推进独立 Session，工作流仅共享外部元数据及可复用定义模板。任务之间 SHALL 不共享变量、临时对象、永久覆盖或数据版本。

#### Scenario: 多任务创建同名对象

- **假设** 同一批次不同脚本创建同名临时表
- **当** 任务并行或顺序分析
- **那么** 本地对象和来源不互相污染
- **并且** 改变任务顺序不改变各任务结果

#### Scenario: 扩展状态效果受能力控制

- **假设** 原入口未请求完整目录和数据版本推演
- **当** 分析普通 DDL 或 VALUES
- **那么** 不默认提交超出既有契约的状态效果
- **并且** 显式扩展的状态效果遵循计划、验证、提交及不确定性规则

### Requirement: 视图模板与读取实例

系统 SHALL 缓存可复用视图定义分析模板，读取实例 SHALL 结合本 Session 可见目录及数据版本，不能共享任务状态或冻结在创建时数据版本。

#### Scenario: 跨任务复用同一视图定义

- **假设** 定义、方言及相关绑定上下文一致
- **当** 多个任务读取该视图
- **那么** 优先复用已解析模板
- **并且** 各读取独立实例化数据来源和本地状态

#### Scenario: 视图绑定上下文不同

- **假设** 本地覆盖或所依赖结构改变
- **当** 读取已缓存视图
- **那么** 重建必要绑定或使用不同键
- **并且** 不复用其他上下文的已绑定结果

### Requirement: 安全离线与资源边界

系统 SHALL 不执行业务 SQL、shell、任意 UDF 或包含脚本代码，SHALL 不依赖完整 Hive 查询编译服务。递归、展开、模型和证据规模 SHALL 有限制及诊断。

#### Scenario: 资源命令和递归超限

- **假设** 脚本含 ADD JAR、包含引用或递归定义
- **当** 分析这些单元
- **那么** 仅记录受控描述或获取文本，不执行代码
- **并且** 循环或超限返回明确诊断，不返回无血缘成功
