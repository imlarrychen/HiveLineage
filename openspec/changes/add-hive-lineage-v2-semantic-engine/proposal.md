# Change: 新增兼容现有需求的 Hive 血缘 V2 语义内核

## Status

方案已获用户批准，并在接口、模型阶段后按“继续完成剩余需求开发”的授权完成具体实现。当前入口、策略和使用方式见 [实现说明](implementation.md)，实际测试及跳过项见 [验收记录](validation.md)；[接口与模型交付](contracts.md) 保留前一阶段记录。

## Why

当前 V1 已覆盖大量实际 SQL，并提供稳定的请求、结果、元数据接入、脚本状态、Join 条件分析和回归素材。随着嵌套查询、作用域和语法组合增加，仅在现有流程上补充场景规则，难以持续保证组合正确性。

本变更新增独立语义内核，以统一语法模型、按需字段绑定、关系与表达式规则推导血缘，同时承接已有 OpenSpec 需求和当前调用契约。语义分析方法升级不要求调用方同步更换 Provider、SQL 文件或结果消费方式。

V1 与 V2 必须可以同时运行，以相同输入和元数据进行比较，帮助用户逐项自验证。

## What Changes

- 新增 V2 实现和独立入口，保留 V1 实现与默认入口；尽量只新增类。
- 新增请求与执行契约适配、按需分析规划、统一语法模型、渐进绑定和语义 IR。
- 将词法、语法、语法归一化、语义绑定、IR 校验和血缘推导作为独立阶段；Bound IR 是血缘分析唯一结构输入。不得沿用 V1 的 SQL 字符串、别名 Map 和启发式来源集合充当内核模型。
- 基于同一内核独立提供表血缘、字段血缘和 Join 条件分析。
- 新增 V1 `HiveMetadataProvider` 适配层，复用现有服务、测试 Provider 及可选缓存。
- 新增脚本级 Session、兼容定义目录、工作流元数据上下文和视图定义模板缓存。
- 新增既有结果适配、完整 V2 结果和独立导出记录，保留任务版本及语句身份。
- 直接复用 `src/test/resources/hql/generated/**/*.sql` 和既有测试元数据，不复制或改写 SQL。
- 新增 V1/V2 双运行、结构化差异、V2 快照和人工核验报告。
- 新建逐场景需求追踪表，登记旧规范、当前行为与 V2 目标之间的差异。

追踪表列入原血缘规范的 53 个场景，以及原 Join 规范的 24 个场景/示例，共 77 行，均登记具体测试、兼容策略及验收结论。

新增三个能力需求：

1. `hive-lineage-v2-engine`：独立内核、组合语义、状态与可扩展性。
2. `hive-lineage-v2-compatibility`：既有 API、功能、Provider、输出和恢复契约。
3. `hive-lineage-v2-regression`：复用测试素材、双运行比较和验收。

本变更不修改或撤销原变更中的 `hive-sql-lineage`、`hive-sql-join-condition` 需求。原需求由本方案承接；仓库既有规范与实现的分歧在追踪表中显式处理。

## Compatibility Baseline

- 现有入口适配采用当前已验证的 API、选项和输出行为，任何变化均进入差异报告。
- OpenSpec 场景逐项建立测试；当前代码未实现的规范要求可以由 V2 新增实现，不计作 V1 行为已存在。
- 同一输入、同一策略无法同时满足相反的预期时，保留充分内部信息，采用命名明确的策略或导出映射分别表达；不能通过静默选择其中一个预期宣称全部兼容。
- 已确认的错误来源、错误绑定和伪字段应修正，并记录为经确认的语义改进。
- V1 输出用于对照；经核验的预期结果用于判断正确性。

## Impact

- 新增生产类优先放在 `com.panfan.hivelineage.v2`，测试和对比入口新增，V1 原实现保留。
- 兼容入口继续接收 `LineageAnalyzeRequest`、返回 `LineageAnalyzeResult`，调用方可以显式替换实现类。
- V2 原生入口提供正向能力集合，支持只分析 Join 条件及后续显式扩展。
- 原 CLI、原 Markdown 快照、原 SQL 和原测试不因本变更被覆盖或改成 V2。
- 原有 Java 8、Maven、Hive Parser 4.0.1 基线保留；必要构建改动在实施时单独说明。
- 对比和快照输出到 `target/lineage-output/v2/`；需要版本管理的已确认标准答案另存专用期望目录，不覆盖 V1 快照。

## Acceptance

V2 达到功能齐平时必须同时满足：

1. 原有两份 OpenSpec 的全部场景都有追踪行和验收结论。
2. 现有选项、表/字段/Join 输出、变量、临时表、CTE、视图、分区、窗口、EXPLODE 及失败恢复都有测试。
3. generated 目录全部 SQL 自动发现并运行；预期错误样例按错误与恢复行为验收。
4. 比较相同输入下的身份、结果、状态和元数据访问，差异全部得到分类与解释。
5. 不得将“未支持”“只完成模型设计”或“未抛异常”计为功能覆盖。
6. 未确认前不开始实现；功能齐平后也不自动替换默认入口、删除 V1 或提交发布。
7. 可以手工构造 Bound IR，在没有 SQL、Lexer、Parser 和 Provider 的情况下验证血缘规则；各阶段具备独立测试及禁止依赖检查。

## Out Of Scope

- 不修改 V1 生产实现、测试 SQL、V1 测试或默认入口。
- 不执行业务 SQL，不连接 Hive 查询服务完成编译，不加载外部 UDF 或 shell 脚本。
- 不实现 TDSQL、图数据库持久化或工作流调度。
- 不让任务 A 的本地推导对象通过共享缓存进入任务 B。
- 不把全部 Hive 方言覆盖作为未经验证的发布承诺。
- MERGE、UPDATE、DELETE、多目标 INSERT、LOAD DATA 声明来源及目录/数据版本推演已按能力扩展；SQL 执行、外部文件内容和未实现的方言仍不在范围内。
