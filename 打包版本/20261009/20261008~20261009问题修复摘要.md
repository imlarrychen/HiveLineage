# 近两天修复问题摘要

## 1. 子查询导致 `INSERT` 目标表识别错误

```sql
INSERT INTO dwd.target_table
SELECT id
FROM ods.source_table
WHERE id IN (
  SELECT id
  FROM ods.filter_table
);
```

此前可能把 `WHERE IN` 子查询的内部节点误认为主写入目标，导致 `dwd.target_table` 为空并报不支持。现在可正确识别：

- 目标表：`dwd.target_table`
- 表依赖：`ods.source_table`、`ods.filter_table`
- 输出字段来源只按主 `SELECT` 的 `ods.source_table.id` 判断。

## 2. 没有 `FROM` 的有效写入被误报不支持

```sql
INSERT INTO dwd.job_status (
  biz_date,
  status,
  batch_id
)
SELECT
  '20261009',
  'SUCCESS',
  make_batch_id('${biz_date}');
```

这类 SQL 没有来源表，但属于有效写入。现在会成功解析：

- `biz_date`、`status`：`CONSTANT`；
- `batch_id`：无来源字段的 `DERIVED`；
- 不生成“源表 → 目标表”或“源字段 → 目标字段”边。

## 3. 非血缘维护语句被误报 `unsupported statement`

```sql
CREATE TEMPORARY FUNCTION f AS 'com.example.F' USING JAR 'hdfs:///udf.jar';

DROP TABLE IF EXISTS tmp.old_data;

TRUNCATE TABLE dwd.daily_snapshot;

ALTER TABLE dwd.daily_snapshot
SET TBLPROPERTIES ('comment' = '日快照表');

CREATE EXTERNAL TABLE IF NOT EXISTS ods.empty_source (
  dt DATE
);
```

这些语句现统一识别为 `IGNORED`：不会计入失败，也不会生成正式血缘。开启 `includeIgnoredStatements` 时可看到具体原因，例如 `DROP_TABLE`、`TRUNCATE_TABLE`、`CREATE_EXTERNAL_TABLE_DDL`。

非法但属于这类维护 DDL 的语句，例如：

```sql
ALTER TABLE dwd.daily_snapshot
SET TBLPROPERTIES（'comment'='错误语法';
```

也不会中断整段血缘任务，但会附带 `INVALID_DDL` 告警。

## 不会被忽略的语句

下列语句可能读写或转换数据，不能按“无血缘语句”处理，仍会进入正式解析或失败路径：

```sql
INSERT INTO dwd.target
SELECT id FROM ods.source;

CREATE TABLE dwd.target AS
SELECT id FROM ods.source;

MERGE INTO dwd.target t
USING ods.source s
ON t.id = s.id
WHEN MATCHED THEN UPDATE SET id = s.id;
```
