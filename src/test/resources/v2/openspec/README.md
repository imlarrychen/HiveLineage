# OpenSpec Join examples

The SQL and JSON fixtures were copied from the existing Join specification's two complete examples:

- `cte-non-continuous`: `openspec/changes/add-hive-sql-lineage-analyzer/specs/hive-sql-join-condition/spec.md`, original line 246 (J-12).
- `exists-non-continuous`: the same specification, original line 371 (J-13).

Expected JSON is the existing specification, not an output snapshot generated by V2. Neither query requires identifier escaping. The test prepends an ignored `USE default` statement so that the query's zero-based script index is 1, exactly as the examples declare.

The examples abbreviate the `rawSql` JSON value with `(...)`. The test preserves those illustrative JSON values in the fixture and checks actual raw SQL separately against the complete SQL fixture. It checks every other JSON field, including the repeated per-record business identities, order, paths, types, complete ON text and the direct/physical objects and fields.

The complete original expected JSON is checked directly against native records. Native direct objects use physical qualified names for scans and logical names for CTE/derived instances; direct fields retain aliases as the specification describes. A separate compatibility assertion checks V1's resolved direct field names without replacing the native expected values.
