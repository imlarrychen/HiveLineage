# Hive SQL 语法覆盖矩阵（v2 开发验证附录）

面向使用者的语法与血缘示例见 [Hive SQL Lineage Reference](hive-sql-lineage-reference.md)。本附录保留原清单的 221 个条目、实现边界及测试证据，供开发验证与缺口追踪使用。

参考文档补充说明：MERGE 示例按动作读取兼容字段贡献时，INSERT 的 name/amount 表达式虽被保留，其独立来源列表仍可能为空；UPDATE 的同名来源不能用来替代 INSERT 证明。详见 [MERGE](hive-sql-lineage-reference.md#write-merge)，不将“有三个写入动作”解释为所有动作的字段关系都完整。
归档日期：2026-10-15。范围：当前工作区的 v2 引擎及接收 v1 `LineageAnalyzeRequest` 的适配入口，前端依赖 Hive 4.0.1。原 `HiveScriptLineageAnalyzer` 的 v1 实现不因本清单而变更支持承诺。

本清单按实现中的语句分派、语法归一化、绑定分支、语法枚举及实际测试整理。每类同时列出支持程度、已覆盖场景与证据、未覆盖场景。Hive lexer 认识某个词、存在某个语法 enum、SQL 能解析，分别不能单独证明它已能生成完整血缘。

初次归档共 221 个分类条目，包含已建模、部分支持、仅审计、明确拒绝和未核实项；函数附表列出当前目录的全部 86 个登记名称。原 138 份 v2 SQL 均能从详细清单中的具体场景定位，历史 18 份资源的证据强度另行标注。字段类型与函数输出随后补充 29 份 SQL，当前共 167 份 v2 SQL；追加证据见[字段表达式补充验证](#字段表达式类型与函数补充验证)。下方逐项缺口表保留初次归档的盘点基准，新增证据通过该补充节及完整资源索引查阅。

## 如何判读支持与覆盖

| 标记 | 含义 |
| --- | --- |
| 已建模 | 对列出的场景有结构化语法、绑定或来源映射；仍受元数据、能力开关和当前行说明限制。分析器不执行 Hive SQL。 |
| 部分支持 | 保留可证明的信息，同时产生 partial、unknown、conditional 或具体诊断；不能等同于完整字段血缘。 |
| 仅语法/审计 | 保存语法、原 SQL 或语句类型；默认不产生正式写入血缘。普通 DDL 还可能有显式开启的 catalog 模拟效果。 |
| 明确拒绝 | 已有失败契约；“拒绝场景已测试”不代表该语法受支持。 |
| 未核实 | 没有足够的真实前端与测试证据，不推断该拼法能被接受或能被正确分析。 |
| 【缺专项测试】 | 当前指定层或文件型集成矩阵缺少该变体的独立证据；不等于已确认实现不支持，也不排除其他层的单元测试。 |
| 【未实现】 | 现有绑定、语法模型或效果模型没有对应能力；增加测试本身不能补足实现。 |
| 【未核实】 | 拼法合法性、前端接受情况或组合语义尚未确认，需先复现再决定支持或拒绝契约。 |

“已覆盖”以实际断言为准。表中引用文件型集成测试、前端单元测试或模型测试时，会分别说明证据层；仅在 SQL 中出现关键字、或只验证构造器/enum，不计作完整集成覆盖。未覆盖列列出明确缺口和待测组合，不表示已穷尽任意深度的全部 SQL 组合。

| 会话与命令 | SET、USE、SOURCE、ADD/LIST/DELETE JAR/FILE/ARCHIVE、CREATE/DROP FUNCTION、TEMPORARY MACRO、RELOAD FUNCTIONS | [S 类](#commands) |

## 分类器盘点说明

[HiveCommandParser](../src/main/java/com/panfan/hivelineage/v2/dialect/hive/HiveCommandParser.java) 的显式入口已按 S01–S09 列出；MACRO/RELOAD 并不经过这些 CommandSyntax 分支，而属于 Other 审计。`SET system/env` 是当前缺少 generated 场景的已实现分支；SOURCE 是当前未执行的审计命令。

[StatementClassification](../src/main/java/com/panfan/hivelineage/v2/api/StatementClassification.java) 还包含 SELECT 的 CURRENT_API/DETAILED 发布分支、VALUES/目录写入、临时/外部 DDL、CTAS/view、mutation/LOAD 等正式候选分支，应与查询/DDL写入清单交叉核对，不能把发布类别误当 SQL grammar 的额外支持项。CREATE/DROP INDEX 仅有兼容分类名，未证明实际语法可达；通用 COMMAND 与 Other fallback 不计入穷尽覆盖。

本节没有给“未找到文件”的 family 虚构 parser 接受结论。尤其是权限、调度和未知 Hive family，未实现语义与未验证前端应分别保留；已有目录中的文件/测试数也不证明所有关键字排列组合均被覆盖。

维护本清单时遵循以下规则：

1. 新增或修改语法分支，更新对应稳定 ID 的支持状态、具体已覆盖场景和剩余缺口；新类别分配新 ID，不以函数名或关键字出现次数代替覆盖证明。
2. 新增文件型 SQL 放入 `src/test/resources/hql/generated`，在对应 suite 的 `scenarioFiles()` 注册，并补独立预期断言；同时更新本清单和[完整资源索引](../src/test/resources/hql/generated/v2_syntax_coverage.md#扩展-sql-文件清单)。
3. 从“缺专项测试”移入“已覆盖”时写明 SQL 与测试方法；只有 inline 单测时保留其证据层，不能标为文件型三模式集成。未实现能力须先落实语法/绑定/效果，再更新支持声明。
4. 明确拒绝、partial、条件效果和未知 schema 都有独立契约；保留这些边界断言，不能仅通过放宽 SUCCESS 期望消除缺口。
5. 运行数字只在实际验证后更新；注明测试范围、模式、JDBC stub 或真实服务环境。文档归档和链接核对不替代代码回归。
