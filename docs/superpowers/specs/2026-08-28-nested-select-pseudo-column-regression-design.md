# 嵌套 SELECT 伪字段血缘回归设计

## 背景

问题 SQL：

```sql
insert into whc.c(field1)
select t.field1
from (
  select a.field1
  from whc.a
  left join whc.b on a.id = b.id
) as t
left join whc.d on t.field1 = d.field1;
```

修复前结果曾错误包含：

```text
whc.a.select -> whc.c.field1
```

正确的字段值只来自 `whc.a.field1`。

## 当前状态与根因

当前 `master` 已能正确解析该 SQL。问题 3 对 `INSERT INTO` 目标节点
`TOK_INSERT_INTO` 的支持，使语句进入完整 Hive AST 血缘路径，不再进入正则回退路径。

修复前，正则回退从外层 `select` 开始寻找 `from <物理表>`。外层第一个
`from` 后面是派生表左括号，无法满足正则中的物理表要求，因此匹配继续跨入内层查询，
把下面的片段误当成外层投影表达式：

```text
t.field1 from (select a.field1
```

后续字段提取把其中的 `select` 当成标识符，最终形成伪来源字段 `whc.a.select`。
完整 AST 路径只读取外层 `TOK_SELEXPR` 的 `t.field1`，再通过派生表投影展开到
`whc.a.field1`，因此消除了伪字段。

## 血缘语义

### 字段血缘

字段血缘表达目标字段值的来源。本例只生成：

```text
whc.a.field1 -> whc.c.field1
```

`whc.b` 和 `whc.d` 没有字段值投影到目标字段，因此不作为该字段的来源列。

### 表血缘

表血缘表达生成目标表时读取或依赖的物理表。本例输入表为：

```text
whc.a
whc.b
whc.d
```

即使右表字段没有进入目标字段值，连接仍可能影响输出行数，因此保留表级依赖。

### Join 条件

开启 Join 条件解析后，去重后的物理连接语义应包含下面两个条件，并把派生表别名还原到物理字段：

```text
whc.a.id = whc.b.id
whc.a.field1 = whc.d.field1
```

当前 Join 模型会按查询块路径记录条件，同一个内层条件可能同时出现在父级聚合记录和
子查询记录中。本次按物理字段对条件去重后断言语义集合，不改变 Join 记录的数量或作用域模型。

## 方案比较

### 方案一：只增加精确回归保护（采用）

当前生产代码已通过问题 3 的根因修复得到正确结果。本次增加用户原始 SQL 的独立
端到端测试和缺陷记录，不再修改生产代码。该方案范围最小，并能防止以后退回正则路径。

### 方案二：过滤 SELECT 关键字

在字段提取阶段排除 `select` 可以隐藏当前伪字段，但不能修复错误的数据流，还可能掩盖
其他非法投影，因此不采用。

### 方案三：重写嵌套查询正则回退

可以增强兜底解析，但完整 AST 已覆盖该合法 SQL。重写正则涉及派生表、CTE、集合运算
和嵌套层级，超出本问题范围，因此不采用。
