# INSERT SELECT * 按位置字段血缘设计

## 背景

当前解析器在处理单来源表的 `INSERT ... SELECT *` 时，会取目标表字段与来源表字段的同名交集。对于下面的表结构：

```text
目标表 whc.whc_hive_01(id, name, age)
来源表 whc.whc_hive_02(id, name, sex)
```

SQL：

```sql
insert into whc.whc_hive_01
select * from whc.whc_hive_02;
```

当前只能生成 `id -> id` 和 `name -> name`，遗漏第三个位置的 `sex -> age`。

## 范围

本次只修复单来源表、未显式指定目标字段的 `INSERT ... SELECT *` 字段映射。

本次不处理：

- 默认库补全；
- `DISTINCT` 误识别；
- 子查询中的 `SELECT` 误识别；
- 多来源 `a.*`、`b.*` 的已有展开行为；
- 与本问题无关的解析器重构。

## 方案比较

### 方案一：按源列和目标列的位置分别展开并对齐（采用）

来源字段按来源元数据顺序展开，目标字段按目标元数据顺序取得，然后按索引建立映射。该方案符合 `INSERT ... SELECT` 的位置赋值语义，也能正确处理字段名不同但位置相同的情况。

### 方案二：继续取同名交集

改动最小，但无法生成 `sex -> age`，不满足本次需求。

### 方案三：优先同名匹配，剩余字段再按位置匹配

看似兼顾两种行为，但会改变 SQL 的位置语义，并在字段顺序变化时产生不可预测映射，因此不采用。

## 设计

### 来源字段展开

单来源 `SELECT *` 在来源元数据可用时，展开为带来源表名的表达式，顺序严格使用来源元数据顺序：

```text
whc.whc_hive_02.id
whc.whc_hive_02.name
whc.whc_hive_02.sex
```

不再用目标字段与来源字段的同名交集作为星号展开结果。

### 目标字段解析

当 SQL 没有显式目标字段列表时，目标字段独立使用目标表元数据顺序：

```text
id
name
age
```

不能再把展开后的来源表达式同时当作目标字段名。

### 位置映射

来源表达式与目标字段按相同索引建立血缘：

```text
whc.whc_hive_02.id   -> whc.whc_hive_01.id
whc.whc_hive_02.name -> whc.whc_hive_01.name
whc.whc_hive_02.sex  -> whc.whc_hive_01.age
```

三条均为 `DIRECT` 血缘。

### 数量不一致

在应用现有静态分区、动态分区目标列对齐逻辑后，如果来源表达式数量与目标有效字段数量仍不一致，整条语句返回：

```text
failureCode = COLUMN_COUNT_MISMATCH
```

不生成部分字段血缘，也不回退到同名交集。

### 元数据缺失

如果来源表或目标表元数据不可用，保留现有元数据缺失处理和告警行为。本次不引入猜测映射。

## 代码边界

主要修改：

- `HiveTargetColumnResolver`：单来源星号只负责按来源元数据顺序展开来源字段；目标字段继续由目标字段解析职责独立取得。
- `HiveScriptLineageAnalyzer`：星号场景下分别解析来源表达式和目标字段，并复用现有数量校验。

不修改 AST 中 `INSERT INTO` 目标节点识别，也不修改关键字过滤逻辑。

## 测试设计

新增独立回归测试，至少覆盖：

1. 同字段数量、字段名不同：断言生成 `sex -> age`，并断言完整三条 `DIRECT` 血缘。
2. 来源字段多于目标字段：断言 `COLUMN_COUNT_MISMATCH`，字段血缘为空。
3. 来源字段少于目标字段：断言 `COLUMN_COUNT_MISMATCH`，字段血缘为空。
4. 同名且同序字段：断言现有正常映射不回归。

相关测试通过后运行完整 Maven 测试集，确认没有改变限定星号、多表星号、集合运算和分区字段的既有行为。
