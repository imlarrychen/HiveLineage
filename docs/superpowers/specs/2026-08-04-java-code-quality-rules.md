# Java 代码质量规则规格

## 目的

本规格将代码质量扫描报告中出现的规则固化为项目级约束，作为后续源码修复、代码评审和质量门禁的统一依据。
规则适用于 `src/main/java` 与 `src/test/java` 下的 Java 源码；如无特别说明，不允许通过关闭规则、增加忽略项或降低阈值规避问题。

## 规则清单

### CQ-01 Java 源文件行数限制

- 每个 Java 源文件最多 1000 行，按物理行统计。
- 项目保持一个源文件一个顶层类型，不通过在同一文件堆积多个类型规避限制。
- 超限代码应按职责拆分，保持公开 API 和业务行为兼容。

### CQ-02 Java 代码行宽限制

- 每行最多 150 个字符。
- 超长的方法调用、条件、字符串拼接和正则表达式应合理换行。
- 换行不得改变字符串、正则表达式或运算符的原有语义。

### CQ-03 方法参数数量限制

- 单个方法或构造器最多 6 个参数。
- 超限时优先按职责提取上下文对象或请求对象，不使用无含义的数组、Map 或可变参数规避限制。
- 上下文对象应保持内聚，避免演变为承载无关状态的通用参数包。

### CQ-04 boolean 表达式复杂度限制

- 单个 boolean 表达式的复杂度最多为 4。
- 超限条件应提取为有业务含义的谓词方法，或拆成层次清晰的分支。
- 拆分后必须保持短路求值顺序、空值判断顺序和原有副作用行为不变。

### CQ-05 禁止给方法参数赋值

- 禁止对方法参数重新赋值，也禁止对参数执行自增、自减或复合赋值。
- 需要转换、补全或对齐参数时，应声明语义明确的局部变量。
- 集合参数的内容是否允许修改由方法契约决定，但不得用修改集合内容规避参数重新赋值规则。

### CQ-06 禁止修改 for 循环控制变量

- 除 `for` 语句自身的更新表达式外，禁止在循环体内修改循环控制变量。
- 需要跳跃扫描时，应使用独立的游标变量、显式 `while` 循环或提取扫描方法。
- 修改结构后必须保持索引边界、跳转位置和循环终止条件不变。

### CQ-07 禁止直接打印和终止 JVM

- 业务源码禁止直接调用 `System.out`、`System.err`、`System.exit` 和 `Throwable#printStackTrace`。
- 运行信息和错误信息通过日志组件或可注入的输出抽象记录。
- CLI 的执行逻辑应返回状态码或抛出明确异常，由最外层启动环境决定进程退出策略。
- 测试代码如需捕获输出，应使用测试专用输出对象，不新增全局标准流修改。

### CQ-08 禁止无用 import

- Java 源码不得保留未使用的 import。
- 职责拆分、方法迁移和重命名完成后，应同步清理失效 import。
- 不使用通配符 import 掩盖依赖关系。

### CQ-09 花括号位置统一

- 类型、方法和控制语句的左花括号放在声明或条件所在行末。
- 右花括号单独占一行；后接 `else`、`catch`、`finally` 时使用 `} else {` 等标准形式。
- 即使分支或循环体只有一条语句，也保留花括号以降低后续修改风险。

### CQ-10 一行一条语句

- 每行最多包含一条可执行语句或声明语句。
- 不在同一行连续声明多个局部变量或书写多个赋值、调用语句。
- `for` 语句头部的初始化、条件和更新表达式不受此规则影响。

### CQ-11 限制 try-catch 嵌套层数

- `try` 或 `try-with-resources` 最多允许嵌套一层。
- 同一生命周期的 JDBC、文件和流资源优先放入同一个 `try-with-resources` 资源声明。
- 如果嵌套代表不同职责，应提取命名方法，而不是继续增加异常处理层级。
- 调整资源声明后必须保持关闭顺序、异常传播和业务返回语义不变。

## 修复约束

- 保持 Java 8 兼容，不修改现有公开接口、请求模型和结果模型。
- 保持 SQL 解析结果、warning 顺序、状态码、集合顺序和 CLI 成功路径语义不变。
- 参数对象和谓词方法按职责命名，避免只为通过扫描进行机械包装。
- 修改循环结构时补充或保留边界场景测试，防止游标跳转产生回归。
- 不引入新的运行时依赖。
- 不修改未跟踪的 `release/` 目录及其打包文件。

## 验收标准

- 截图中涉及的 CQ-02 至 CQ-11 问题全部修复。
- `src/main/java` 与 `src/test/java` 下不存在超过 1000 行的 Java 文件。
- 完整 Maven 测试退出码为 0，无失败和错误。
- 质量检查能够报告具体规则、文件和行号，便于后续定位。
- `git diff` 不包含 `release/` 或与本次质量修复无关的变更。
